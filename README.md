# shadcn-family-tree

A vertical, generation-layered family tree component for shadcn/ui. People are
shadcn `Card`s laid out by generation, joined by relationship connectors. Click
anyone and the whole tree re-labels itself around them — _father_, _step-mother_,
_half-brother_, _first cousin once removed_ — all calculated from the graph.

**[shadcn-familytree.ryck.dev](https://shadcn-familytree.ryck.dev)** — docs, a
live [demo](https://shadcn-familytree.ryck.dev/demo), and the registry.

```bash
npx shadcn@latest add https://shadcn-familytree.ryck.dev/r/family-tree.json
```

Or register the namespace once in your `components.json` and install by name:

```json
{
  "registries": {
    "@familytree": "https://shadcn-familytree.ryck.dev/r/{name}.json"
  }
}
```

```bash
npx shadcn@latest add @familytree/family-tree
```

```tsx
import { FamilyTree } from "@/components/ui/family-tree"

const people = [
  { id: "a", name: "Ada Vance", sex: "female" },
  { id: "s", name: "Sam Vance", sex: "male", partnerIds: ["a"] },
  { id: "i", name: "Iris Vance", sex: "female", parentIds: ["a", "s"] },
]

<div className="h-svh">
  <FamilyTree people={people} defaultFocusId="i" />
</div>
```

## What it does

- **Generation-layered vertical layout.** Each couple sits centred over the
  children below them; siblings share a row; a subtle rule marks each generation.
- **Compact cards.** Name led by a sex icon, then nickname and lifespan, then
  the relationship and a location that links out to Google Maps.
- **Calculated relationships.** Selecting a person recomputes every badge
  against them, walking both pedigrees to the nearest common ancestor. Handles
  half-siblings, step-relations, in-laws, and Nth cousins M times removed.
- **Focus-relative branch colours.** The four grandparent lines of whoever you
  are viewing as take slots 0–3 of the palette; the focus person's own line
  takes a fifth. The colours always answer "which side of the family is this?"
- **Two focus modes.** `highlight` dims everyone off the line and keeps the tree
  stable; `isolate` filters them out and re-lays out around the line.
- **Pan and zoom.** Drag, wheel, pinch, fit-to-screen, centre-on-selection.
- **Zero runtime dependencies.** The layout engine, kinship calculus and
  viewport are all in the source you install.

## Data model

Relationships are flat — point at parents and partners by id — and the component
derives the couples (_unions_) from that. Every distinct parent pair becomes its
own union, which is what separates half-siblings from full siblings with no
extra bookkeeping.

Only `id`, `name` and `sex` are required. Use `partnerships` instead of
`partnerIds` when you want a status or dates; that is what styles the connector
(solid for a marriage, dashed for a partnership, hatched for a divorce).

Bad input produces development-only console diagnostics rather than exceptions:
unknown ids, more than two parents and ancestry cycles are reported and then
worked around.

## Repository

```
packages/family-tree   the component — layout, kinship, branches, viewport, UI
packages/ui            shadcn primitives (generated by the shadcn CLI)
apps/web               TanStack Start site: landing, /demo, /docs
registry.json          registry manifest, built to apps/web/public/r
```

The component's source imports shadcn primitives as `@/components/ui/card` and
`@/lib/utils` — the paths a _consumer_ has — so the registry can ship the files
unmodified. Inside the monorepo those specifiers resolve through thin re-export
shims in `apps/web/src/components/ui/`, which makes the app an honest stand-in
for a real consumer project.

## Development

```bash
pnpm install
pnpm dev              # the site on :3000
pnpm test             # layout and kinship unit tests
pnpm typecheck
pnpm lint             # oxlint
pnpm lint:fix
pnpm format           # oxfmt (add --check in CI)
pnpm registry:build   # regenerate apps/web/public/r
```

Rerun `pnpm registry:build` after changing anything under
`packages/family-tree/src` — the built JSON is what consumers install, and it is
served from `/r/family-tree.json` on the deployed site.

Linting is [oxlint](https://oxc.rs) and formatting is
[oxfmt](https://oxc.rs), both configured at the repo root
(`.oxlintrc.json`, `.oxfmtrc.json`) and run in a single pass over every
workspace rather than per package. oxfmt handles Tailwind class sorting
natively, so `prettier-plugin-tailwindcss` is no longer needed.

Built with shadcn/ui (Base UI), TanStack Start, Tailwind v4 and lucide, on Node 24 (LTS).
