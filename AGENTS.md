# AGENTS.md

## Base UI, not Radix

This project uses Base UI. Its documentation can be found at https://base-ui.com/llms.txt.

Base UI components do not have the same API as Radix UI; this includes props, data
attributes, or components.

There is no `asChild` prop on any component; instead, the `render` prop is used. Read Base
UI's composition guide for details on how to use render:
https://base-ui.com/react/handbook/composition.md.

Always consult the Base UI llms.txt doc before building components with Base UI to ensure
the correct patterns are being used.

One local consequence worth knowing: rendering a `Button` as a link needs care. With the
default `nativeButton` it warns, and `nativeButton={false}` applies `role="button"`, which
takes link semantics away from assistive tech. For anything that navigates, use
`buttonVariants({ ... })` as a class on a real `Link`/`a` instead — see
`apps/web/src/components/not-found.tsx`.

## Layout

- `packages/family-tree` — the component that ships. This is the registry payload.
- `packages/ui` — shadcn primitives, generated by the CLI.
- `apps/web` — the TanStack Start site, prerendered to static HTML.
- `registry.json` → built into `apps/web/public/r`.

## Rules

**Rerun `pnpm registry:build` after changing anything under `packages/family-tree/src`,**
and commit the result. CI rebuilds and diffs it, so a stale `apps/web/public/r` fails the
build.

**`packages/ui` is a stand-in for a consumer's own shadcn install, not a place to
customise.** `registry.json` lists `button`, `card`, `badge` and friends as bare
`registryDependencies`, so consumers get those from the default shadcn registry — never
from this repo. Editing `packages/ui/src/components/*` would make `apps/web` demo
something nobody can install. Style site chrome with classes instead.

**`packages/family-tree` imports consumer-shaped paths** (`@/components/ui/card`,
`@/lib/utils`) so the registry can ship its files unmodified. Inside the monorepo those
resolve through the one-line re-export shims in `apps/web/src/components/ui/`.

**Every route is prerendered.** There is no server at runtime. `crawlLinks` only finds
what is reachable from `/`, so an unlinked route has to be named in `pages` in
`apps/web/vite.config.ts` — `/gonzalez` is there for exactly this reason.

## Style

oxlint and oxfmt at the repo root, one pass over everything. No ESLint, no Prettier, no
`prettier-plugin-tailwindcss` — oxfmt sorts Tailwind classes natively.

Formatting is **no semicolons, double quotes, 2-space indent, 80 columns, ES5 trailing
commas**. Run `pnpm lint:fix` and `pnpm format`.

When a lint rule is switched off, say why in a comment above it. Both this repo and
rtk-query-devtools do this consistently.

## Sibling project

`rtk-query-devtools` shares this project's palette, fonts, header/footer patterns, lint and
format configs, and Base UI + TanStack Start stack. Changes to shared conventions —
`packages/ui/src/styles/globals.css` tokens, `.oxfmtrc.json`, `.oxlintrc.json`,
`site-header.tsx` / `site-footer.tsx` / `lib/link.ts` — should land in both so they keep
reading as one family.
